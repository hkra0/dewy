# aqua 优化实施记录

本轮落实 `aqua-optimization-plan.md` 的 P0–P3。P4 鱼缸灯按原方案留在后续阶段，需先确认灯具时序并完成多灯隔离设计。本轮不下发设备配置、不刷写实机、不部署 Worker。

## 实现

- `aqua_model.h`：无 Arduino、FastLED、网络依赖的采样质量、报警、提醒、触摸状态机。`config_protocol.h` 使用可在主机运行的 ArduinoJson 解析同一份配置协议；非法配置整体拒绝。
- DS18B20 固定 12 位转换，等满 750 ms 才读取，每 5 秒启动一轮。首次转换前无有效值；缓存不作为新样本。连续三次失败或有效样本超过 15 秒后失效，上报 null。85℃作为可能的上电/内部复位读数排除，-127℃作为库的断线标记排除。
- 网络任务独立于硬件主循环，使用单槽队列传递最新快照和配置；TCP 连接预算 250 ms、MQTT 握手读超时 1 秒、mDNS 查询预算 250 ms，重试退避至 30 秒。WiFi/Broker 断线不触发持续重启。配置只在主循环应用，避免两个任务同时修改运行参数。
- 四类报警独立维护事件、触发时间、确认和静默期限。温度报警连续三次新鲜样本确认/恢复，高低温恢复回差 0.5℃。故障由连续失败/过期确认，连续三次成功恢复；故障提示约 20–30 秒内出现（取决于失败发生在采样周期中的位置）。温差缓冲每 30 秒保存一点，比较窗口两端三点中位数；连续样本间隔超过 15 秒重新预热，恢复线为触发阈值的 70%。温差事件保留原始方向。
- 报警最多闪烁 15 分钟，短按或超时后静默 6 小时。NVS 恢复活动报警时保守静默；无可信时钟时不会重复闪烁，时钟恢复后建立可持久化期限。静默不清除报警事实。
- 提醒保留 `daily` 和 `temperature_accumulation`。积分按新鲜样本间的实际单调时间增加，最大连接间隔 15 秒，不补停机区间。每天只在窗口内首次满足条件时评估一次。低温/高温/探头报警恢复确认完成前暂停提醒和积分；温差报警保留独立事实。
- 触摸防抖 50 ms，释放时区分短按/1.5 秒长按；本次手势期间出现闪烁报警就只确认报警。短按喂食、长按跳过、10 秒内短按撤销恢复完整快照及应计进度。默认跳过保留积分，结束窗口自动跳过；可选清空整轮积分。
- 运行状态按动作立即写 NVS，积分每 30 分钟检查点写入；相同配置重放不重复写。完整日期防止窗口内重启、跨年和回拨后重复评估；时间未同步不启动日历提醒、不伪造喂食时间。
- MQTT v2 是完整快照：失效/缺失字段清空，保存最后接收时间；超过 30 秒标记过期并停止归档旧快照。旧协议仍支持局部更新；`fed=0` 清除残留时间，固件回退时清理新状态字段。通用指标元数据支持 `continuous/latest`，`fed` 和积分取最新，日期/状态元数据不新增数据库列。
- 现有卡片显示提醒原因、积分、最近真实喂食、下次允许日期、报警及确认/静默状态。节点设置支持 boolean/select，保存后轮询实际回报，区分等待、已生效、拒绝。旧固件无新字段时保留原卡片，无 viewer key 保持静默。

## 配置与迁移

真实 `hardware_config.toml` 已同步 aqua 的试运行 schema（高温 31.5℃、关闭持续低温报警、积分模式）；示例文件保留通用 `daily` 默认。真实配置受 Git 忽略，应随部署单独同步。

已有非空 `node_settings` 缺少模式时补 `daily`，同时保留原先启用的低温报警、让暂停上界沿用旧高温阈值，避免升级自动改变提醒策略。`feed_reset_hour` 缺少新字段时迁移到 `feed_start_hour`。已保存的旧温度阈值继续保留；启用 aqua 试运行策略应在设置页明确保存相应模式、阈值和开关。

旧 `feed_st` 的 `tm_yday` 无年份，无法证明真实喂食日期。迁移保留原 NVS 键供诊断；若旧记录为已喂食，首次同步日期后保守跳过当天提醒，不伪造 UTC 喂食记录。之后使用完整版本化状态。

构建目标由 `platformio.ini` 的 `custom_node = aqua` 显式指定，也可用 `DEWY_NODE` 覆盖；构建脚本解析 TOML，不再正则匹配或回退到另一节点。构建凭据从目标节点读取，不打印。

## 验证

```text
python -m unittest discover -s tests -t .
node tests/aqua_frontend.mjs
pio test -e native
pio run -e esp32s3mini
```

native 测试运行固件使用的 C++ 状态机和 JSON 配置解析器，覆盖 13.5℃第三天/18.6℃次日、每天只评估一次、手动/自动跳过、温度暂停、撤销、无效和缓存样本、温差覆盖与缺样、回差与静默、手势、跨年/校时/重启和 millis 回绕、配置原子拒绝与重放。Python/JS 回归覆盖快照清空、离线、固件回退、聚合/归档语义、schema 校验、兼容迁移、boolean/select 序列化和中英文卡片。

浏览器使用本地模拟 API 核对中文暗色卡片及动态设置控件。模拟验证不等同于真实 MQTT、触摸电气时序或 LED 观感验收。部署后仍需实机检查拔插探头、WiFi/Broker 长断线及恢复、NVS 断电恢复、报警触摸和灯效。未新增静态 JS 模块或改 Worker 打包规则。

本次验证结果：239 项 Python 测试、13 项 native 测试和前端回归测试通过，ESP32S3 构建成功；浏览器另核对了英文状态文案。
